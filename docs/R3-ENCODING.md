# R3 — форматы записи и восстановление после сбоя

27 октября 2026. **Сделаны MP3, FLAC, Opus и WAV с восстановлением после
`kill -9` и выбор формата в окне.**

## Как пишется запись

`RecordingSink` (`shared/src/EliteRec.Encoding`) пишет пару файлов в выбранном
формате: общий микс (моно) и стерео (L — микрофон, R — система).

| Формат | Кодер | Микс / стерео | Что чинится после сбоя |
|---|---|---|---|
| MP3 (по умолчанию) | `libmp3lame` | CBR 128 моно / CBR 192 `STEREO` (не joint) | Отрезается недописанный кадр |
| FLAC | `libFLAC`, уровень 5, 16 бит | без потерь | Отрезается недописанный кадр (CRC-16); STREAMINFO остаётся «длина неизвестна» — допустимо по RFC 9639 |
| Opus | `libopus` (multistream), кадр 20 мс, свой Ogg | 32 кбит/с моно / 2×32 кбит/с: два независимых моно-потока | Отрезается оборванная страница Ogg (CRC32), последняя помечается концом потока |
| WAV | свой | PCM16 | Размеры RIFF/data пишутся по длине файла, полкадра отрезается |

**Opus и разделение каналов.** Обычный стерео-режим Opus при сжатии может
частично смешивать каналы (как joint stereo в MP3). Поэтому стерео-файл
кодируется двумя независимыми моно-потоками: раскладка семейства 1, 2 потока,
0 связанных (RFC 7845 §5.1.1). Тест подаёт тон слева и тишину справа:
после кодирования и декодирования правый канал тише левого более чем в 1000 раз.
Контейнер Ogg пишется своим кодом (RFC 3533): страница примерно раз в секунду
и перед каждым сбросом на диск; libogg не нужна.

- Пока идёт запись, файлы скрыты: `.имя.mp3.part` и `.имя_stereo.mp3.part`
  (для остальных — `.flac.part`, `.opus.part`, `.wav.part`) в «Записи EliteRec». Каждые 5 с
  аудио они сбрасываются на диск (`fsync`).
- «Стоп» дописывает хвост кодера (у FLAC — STREAMINFO с длиной и MD5, у WAV —
  размеры), делает `fsync` и переименовывает части в итоговые файлы.
- MP3 — без Xing/ID3-тегов: у CBR-потока каждый кадр самодостаточен.
- Формат выбирается в окне («Формат записи»), сохраняется в
  `~/.config/EliteRec/devices.json` (поле `Format`) и заблокирован во время
  записи. Отдельное окно настроек — R5.

**Имя библиотеки FLAC различается по дистрибутивам:** Debian 13 —
`libFLAC.so.14`, Ubuntu 24.04 / Mint — `libFLAC.so.12`. Библиотека ищется по
списку имён (`Native/Flac.cs`). В зависимостях .deb (R6) указать пакет Debian 13
(`libflac14`), а не Ubuntu.

**Отступление от плана.** В плане были «части по ходу и сборка итоговых
файлов». Для MP3 это не нужно: поток кадров уже и есть «части», а сборка
после падения сводится к отрезанию недописанного последнего кадра. Для
FLAC и WAV хватило того же подхода: обрезать по последнему целому кадру и
дописать то, что обычно пишется при завершении (размеры WAV).

## Восстановление

`RecordingRecovery`:

- `Find(папка)` ищет скрытые части. Части, изменённые меньше 15 с назад,
  пропускаются: они могут принадлежать идущей записи.
- `Recover` отрезает недописанный хвост (MP3 — проверка каждого заголовка
  кадра; FLAC — поиск последнего заголовка кадра с CRC-8 и проверка CRC-16
  кадра; Opus — последняя страница Ogg с верным CRC32; WAV — кратность
  размеру отсчёта), чинит заголовок WAV, помечает конец потока Opus и
  переименовывает части в обычные файлы. Если имя
  занято, добавляется `-2`, `-3`; существующие файлы не перезаписываются.
- `Discard` удаляет части.

В окне при запуске показывается карточка «Найдена незавершённая запись от
27.10 13:30, длительность 00:11:40» с кнопками «Восстановить» и «Удалить».

Потери: после `kill -9` данные остаются в кэше ОС, поэтому теряется только
недописанный кадр и аудио в буфере синхронизатора (около 0,25 с). Opus держит в памяти до 1 с звука до записи страницы, поэтому после
`kill -9` теряет до 1 с. При отключении питания — до 5 с (интервал `fsync`)
у всех форматов.

## Проверки

| Проверка | Результат |
|---|---|
| Тесты | 53 прошли (+9 форматы/восстановление в Core.Tests, +1 формат в App.Tests) |
| Opus: независимость каналов | Тон слева, тишина справа → после декодирования RMS справа < 1/1000 левого |
| Opus: длина и конец потока | Все CRC страниц верны, флаги BOS/EOS, длина ровно 2,000 с |
| Оборванный Opus | Отрезана последняя оборванная страница, новая последняя помечена EOS |
| FLAC-пара | STREAMINFO: 48 кГц, 16 бит, 1/2 канала, длина 96 000 отсчётов за 2 с |
| Оборванный FLAC | Обрезан ровно по началу последнего кадра, целая часть совпадает побайтно |
| WAV после сбоя | Нулевые размеры и полкадра → файл побайтно равен нормально завершённому |
| MP3-пара | Каждый кадр: микс MONO 128, стерео STEREO 192 |
| Обрезанный кадр в конце части | Отрезается, длина равна целым кадрам |
| Конфликт имён / удаление частей | `-2` вместо перезаписи; `Discard` удаляет |
| `kill -9` на 13-й секунде реальной записи (виртуальные источники) | Свежие части не тронуты; через 16 с восстановлено MP3 11,66 с, FLAC 11,63 с, Opus 10,99 с (оба декодируются GStreamer), WAV 11,83 с; частей не осталось — [kill.json](r3-results/kill.json) |

Отключение питания и слабый ПК (A6/HDD) не проверялись.

```bash
python3 scripts/r3-kill-smoke.py --format mp3   # также flac, opus, wav
dotnet tools/EliteRec.Recorder/bin/Release/net10.0/EliteRec.Recorder.dll --recover "ПАПКА"
```

`Recorder` пишет `--format mp3|flac|opus|wav` (по умолчанию WAV — на нём построены
проверки R2). Для проверки FLAC и Opus скрипт использует `gst-launch-1.0` и
`gst-discoverer-1.0`.
