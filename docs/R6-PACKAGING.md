# R6 — поставка

28 октября 2026. **Сделаны пакет `.deb` и обновление с канала**, проверены на
Debian 13 и Ubuntu 24.04 (основа Linux Mint 22). Канал EliteRec на сервере ещё
не развёрнут — см. «Что осталось».

## Пакет

Сборка: `packaging/build-deb.sh --version 0.1.0` → `artifacts/EliteRec-0.1.0.deb`
(36 МБ, распакованный 114 МБ). Устроен как пакет EliteSIP для Linux
(`Linux EliteSip/tools/build-deb.sh`) — те же пути и правила.

| Путь | Что |
|---|---|
| `/opt/eliterec/EliteRec` | программа с рантаймом .NET (self-contained, ReadyToRun) |
| `/opt/eliterec/eliterec-updater` | обновляльщик (тот же рантайм) |
| `/opt/eliterec/provisioning.json` | заводская настройка: канал, пара Basic, открытый ключ линии |
| `/usr/lib/systemd/system/eliterec-updater.{service,timer}` | служба обновления от root и такт раз в 10 мин |
| `/var/lib/eliterec/updates` (1777), `/var/lib/eliterec/updater` (0700) | отметки «пишу»; скачанные пакеты |
| `/usr/share/applications/eliterec.desktop` | ярлык в меню («Запись звонков») |
| `/etc/xdg/autostart/eliterec.desktop` | автозапуск в трей (`--tray`); менеджер выключает у себя |
| `/usr/share/icons/hicolor/{16…512}/apps/eliterec.png` | значок |
| `/usr/share/doc/eliterec/` | copyright, changelog с коммитом сборки |

- **Самодостаточная публикация:** ни в EliteLinux, ни в Mint .NET не стоит.
  ReadyToRun сокращает JIT при запуске — окно появляется за 0,77 с на SSD
  (на HDD дольше; на A6 не замерено).
- **Зависимости с альтернативами** под обе системы — урок EliteSIP, у которого
  одна жёсткая `libicu74` сломала установку на Debian 13:
  `libicu76 | libicu74 | libicu72`, `libflac14 | libflac12t64 | libflac12`; плюс
  libpulse0, libmp3lame0, libopus0, X11-библиотеки Avalonia, fontconfig,
  xdg-utils. Рекомендуются `pipewire-bin | pulseaudio-utils` («Прослушать» в
  самопроверке) и `libgl1` (отрисовка через видеокарту).
- **Автозапуск** — сразу в трей: окно не появляется при каждом входе в систему.
  Если панель не показывает трей, окно сворачивается в панель задач.
- **Второй запуск** (ярлык при работающем автозапуске) показывает окно первого.
- `postinst` создаёт общий каталог отметок и включает таймер; `purge` убирает
  `/var/lib/eliterec`. Записи и настройки менеджера в его профиле пакет не трогает.
- `EliteRec --check-codecs` — диагностика установки: секунда тишины в каждом
  формате; код 0 — все форматы пишутся.

## Обновление с канала

Как у EliteSIP для Linux (`Linux EliteSip/docs/PORT-PLAN.md`, W-L7), со своим
каталогом и ключом и с правилом «никогда во время записи».

**Канал** — сервер `elitesip_update` (`update.elitesip.vip:8081`), каталог
`releases/eliterec/linux/`: `current.json` и `EliteRec-<версия>.deb`, та же общая
пара Basic, что у EliteSIP; манифест кэшируется 5 минут, пакет неизменяемый.
Правка сервера — ветка `eliterec/releases` (коммит `b51d868`), тест `TestEliteRecReleases`.

**Манифест** — тот же конверт, что у EliteSIP: `{"payload": base64, "signature":
base64}`, подпись Ed25519 по байтам payload (format, version, url, sha256, size,
published_at, notes). **Ключ свой у линии EliteRec**: манифест EliteSIP, подложенный
в каталог EliteRec, и наоборот, не пройдёт. Закрытый ключ —
`~/.config/EliteRec-release/releases.key` (0600, вне Git); открытый
`5aEKL0uFl650KpaBCFpkZrBMAkzlrFAcfereKsELVBI=` — в `provisioning.json` пакета.

**Такт** (`src/EliteRec.Updater`, `eliterec-updater.service` от root, таймер — через
5 мин после загрузки и раз в 10 мин):

1. манифест с паролем канала; подпись ключом линии; пакет — только https, тот же
   хост и каталог EliteRec; версия строго новее установленной (`dpkg-query`);
2. пакет — в закрытый каталог службы; SHA-256 и размер из подписанного манифеста,
   иначе удаляется;
3. **отметка «ставлю»** (`/run/eliterec-updater/installing`), затем проверка
   отметок «пишу»: идёт запись хоть у кого-то — установка откладывается до
   следующего такта;
4. EliteRec у всех пользователей закрывается штатно (SIGTERM), сеанс (DISPLAY,
   D-Bus) запоминается;
5. `apt-get install` отдельным юнитом `eliterec-install` (`systemd-run --wait`):
   сама служба в песочнице `ProtectSystem=strict` в `/opt` писать не может;
6. EliteRec поднимается обратно в трей в сеансе каждого
   (`systemd-run --user -M <пользователь>@`), и после неудачной установки — прежний.

**«Не во время записи»** (`UpdateCoordination`): приложение перед записью сначала
ставит отметку «пишу» (`/var/lib/eliterec/updates/recording-<pid>`), потом
проверяет «ставлю»; служба — наоборот. При таком порядке хотя бы одна сторона
видит другую: либо установка ждёт, либо запись не начинается («Сейчас ставится
обновление EliteRec — меньше минуты. Программа перезапустится сама, тогда
начните запись»). Отметка «пишу» проверяется по живому процессу
`/opt/eliterec/EliteRec` — забытая после сбоя или подделанная не блокирует
обновления; «ставлю» живёт в RuntimeDirectory службы и исчезает вместе с ней.
Механизм обновлений записи не мешает: нет каталога (запуск не из пакета) —
запись идёт.

**Выпуск и выкладка:**

```bash
packaging/release.sh --version 0.1.1 --notes "что нового"   # тесты, пакет, манифест, подпись, проверка, метка
packaging/publish.sh --version 0.1.1                        # пакет, потом манифест; сверка того, что отдаёт канал
```

Доступы выкладки — `~/.config/EliteSIP-release/publish.local.json` (тот же
сервер, что у EliteSIP).

## Что осталось

1. **Развернуть сервер:** влить ветку `eliterec/releases` в `elitesip_update`
   (`dev` → `main`, деплой GitLab CI).
2. **Первый выпуск:** `packaging/release.sh --version 0.1.1`, затем
   `packaging/publish.sh`. Машины с пакетом 0.1.0 без канала (собранным без
   `--provisioning`) нужно один раз переставить руками — у них нет настройки канала.
3. **Проверить на живой машине:** установка от root (`sudo`), подъём EliteRec в
   графическом сеансе после обновления (`systemd-run --user -M`), отказ записи
   во время установки — в окне.
